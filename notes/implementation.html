Important implementation choices

  • Trusted, unsandboxed execution. Requires Node 22.19+ and Python 3.12+ on PATH. Ordinary filesystem, networking and Python libraries are available. CodemodeExecutionEnv replaces the old name, with a deprecated CodemodeSandbox compatibility alias.
  • Portable IPC. Authenticated loopback TCP carries length-prefixed JSON, separate from stdout/stderr. Windows inherited-descriptor differences motivated this choice. A 64 MiB frame ceiling bounds transport; oversized frames are execution errors.
  • Native persistence. Runtime store values are opaque Uint8Array pickle bytes, base64-encoded throughout IPC and versioned codemode-py-store session entries. Limits are 256 KiB per value and 2 MiB total, measured as raw serialized pickle bytes. Failed scripts publish no writes; load returns a copy; storing None deletes.
  • Returns versus output. Returns must be JSON-compatible: top-level None becomes {}, nested None becomes JSON null, and unsupported values raise a script error. text() retains its repr() fallback.
  • Host-owned completion. Windows could reset the socket before large terminal store frames arrived. The runner now remains alive after sending completion, and the host terminates it after consuming the result. Background tasks are cancelled but their finalizers are not awaited: an event loop cannot bound a synchronously blocking finalizer. Host calls are aborted and process cleanup supplies the independent bound.
  • Process trees. POSIX uses detached process groups with escalation; Windows uses kill-on-close Job Objects established before user code. Job setup failure fails startup instead of falling back to unreliable descendant killing. Bridge-loss cleanup covers abrupt host death.
  • Declarations are complete snippets. Keep imports and supporting types, not just the signature line. Separate snippets containing future imports cannot simply be concatenated. Multi-part allOf falls back to Any; JSON arrays remain lists; Python 3.12 cannot precisely type extra TypedDict keys. ASCII aliases handle hard keywords, while soft keywords remain valid identifiers.
  • Adapter details. Injected host functions take positional arguments; use dictionaries for options, not Python keyword arguments. Discovery aliases use getattr(tools, entry["name"]); brackets address original names. Executions are serialized to protect branch-sensitive store updates. Runtime cwd follows the SDK session workspace.
  • Small local utilities. Search, usage aggregation, temporary output and preview helpers replace unavailable private Pi imports. Model calls retain a four-call concurrency limit and check cancellation before leaving the queue. Spill files intentionally survive so subsequent tools can retrieve them.

Verification and test restraint

The existing harness was ported where its intent still applied. VM isolation, frozen namespaces, WASM assets, JavaScript stack/throw behavior and stalled-promise tests were discarded. Python calls start when awaited or scheduled, not merely when a coroutine object is created.

New tests were restricted to complex regressions: cancellation-resistant tasks, a real process-tree lifecycle matrix, multiline-literal preservation, and executable generated declarations with reference budgets and annotation shadowing. Adapter scenarios were ported and consolidated rather than multiplied.

  • Final assembled build/tests: Windows, Node 25.9 / Python 3.13.14; WSL Ubuntu 24.04, Node 22.19 / Python 3.12.3. All 65 tests pass on each.
  • Lifecycle coverage: actual descendants on success, timeout, abort, runner crash and external host death, including Windows handle-inheritance challenges. POSIX zombie processes count as terminated, not live descendants.
  • Adapter coverage: real Pi resource loader and compiled extension, builtin replacement, hooks, permissions, branch persistence, model credentials, concurrency/costs, loadouts, truncation and saved images. Model responses are controlled by the harness, not evidence of live-provider compatibility.
  • Packaging: both package dry-runs succeed; adapter-test strict typechecking passes; current dependency audit reports zero vulnerabilities. Prior implementation/review also verified clean root installation.

Boundaries and next-use notes

Lifecycle management is not hostile-code containment. Trusted scripts can deliberately escape ordinary POSIX groups or tamper with runtime internals. Cancellation cannot undo remote side effects, and async finalizers are not guaranteed to finish. Pickle data must be trusted; it is not a safe interchange format for untrusted session input.

Publish the runtime before its adapter dependency. For local use, run npm ci, add +codemode to Pi's defaultTools, and load with pi -e .. Using --tools codemode also removes ordinary tools from nested availability. Verified host APIs are Pi 1.0.2; future allowed versions were not individually tested.
